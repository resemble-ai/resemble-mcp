Detect whether a piece of writing was generated by an AI language model or written by a human. One endpoint, one text per call, JSON in and JSON out.

`POST https://app.resemble.ai/api/v2/text_detect`

By default the request is asynchronous: the API responds immediately with `status: "processing"` and you poll `GET /text_detect/{uuid}`. Include `Prefer: wait` to block until completion.

**Access:** available to teams on a current billing plan (billed as one Text Detection unit per completed job) and to `detect_beta_user` accounts. Accounts without access receive a `400` with `"This feature is not available for your account"`; teams that are out of entitlement receive a `402`.

## Request Schema

```ts
interface TextDetectRequest {
  text: string;                  // at least 25 words, at most 100,000 characters
  threshold?: number;            // 0.0-1.0 cutoff on the model's AI probability (default 0.5)
  thinking?: "low" | "medium" | "high"; // leave at "low" (default)
  callback_url?: string;         // HTTPS webhook called on completion
  zero_retention_mode?: boolean; // do not store the text; omits text_content from responses
}
```

### The 25-word minimum

Text under 25 words is not scored. Below that length no model or threshold separates casual human writing from AI text, so the API rejects the request with a `400` rather than returning a guess. Count words before you call, and if you have several short messages from the same author, concatenate them into one request.

### Read window

The model reads roughly the first 350-400 words (512 tokens). Longer text is scored on its beginning. For whole-document coverage, split into ~300-word chunks and submit each.

### Cold starts

The text model scales to zero when idle. Warm requests complete in about 2 seconds, but the first request after idle can take 3-4 minutes while the model loads, and jobs queued behind a cold start can take longer. With `Prefer: wait`, set your client timeout to at least 300 seconds; when polling, expect the first poll cycle to last several minutes.

## Example

```bash
curl --request POST "https://app.resemble.ai/api/v2/text_detect" \
  -H "Authorization: Bearer $RESEMBLE_API_KEY" \
  -H "Prefer: wait" \
  -H "Content-Type: application/json" \
  --max-time 320 \
  --data "$(jq -n --arg text "$TEXT" '{text: $text}')"
```

## Response

```json
{
  "success": true,
  "item": {
    "uuid": "8452e246-...",
    "status": "completed",
    "prediction": "ai",
    "confidence": 0.9973,
    "text_content": "...",
    "privacy_mode": false,
    "created_at": "...",
    "updated_at": "..."
  }
}
```

| Field          | Meaning |
|----------------|---------|
| `status`       | `processing`, `completed`, or `failed`. Only `completed` carries a verdict. |
| `prediction`   | `ai` or `human`. Rarely `uncertain`, meaning the model declined to score the text; report it as "not enough text to judge", never as human or AI. |
| `confidence`   | 0.0-1.0. How sure the model is of `prediction`. **Not an AI probability**: `confidence: 0.95` with `prediction: "human"` means strongly human. |
| `text_content` | The submitted text, echoed back. Omitted when `zero_retention_mode` was set. |

Always present `prediction` and `confidence` together, and never present a verdict as proof of who wrote the text.

## Other endpoints

- `GET /text_detect/{uuid}` - fetch one text detection
- `GET /text_detect` - list the team's text detections, newest first, paginated

## Known behaviour by register

- Long-form (articles, essays, business and academic writing): under 0.2% of human text flagged, over 99% of AI text caught.
- Forum and social posts: about 2-3% of human posts flagged.
- Casual chat just over 25 words: about 4% false-positive rate on human text.
- Code review comments and PR descriptions: about 5% of human write-ups flagged.
- Short AI abstracts under 150 words: roughly 85% caught.
